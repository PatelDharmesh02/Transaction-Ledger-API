# Transaction Ledger API

A small FastAPI application backed by PostgreSQL. It supports account creation, credit/debit transactions, balance lookup, and paginated transaction history.

## Requirements

- Python 3.10 or newer
- PostgreSQL

## Setup

1. Create a PostgreSQL database:

   ```sql
   CREATE DATABASE transaction_ledger;
   ```

2. Update `DATABASE_URL` in `.env` with your PostgreSQL username and password.

3. Create and activate a virtual environment:

   ```bash
   python -m venv .venv
   source .venv/bin/activate
   ```

   On Windows, activate it with `.venv\\Scripts\\activate`.

4. Install the dependencies and run the API:

   ```bash
   pip install -r requirements.txt
   uvicorn app.main:app --reload
   ```

The application creates the tables on startup. Open <http://127.0.0.1:8000/docs> to try the endpoints.

## Endpoints

- `POST /accounts` — create an account with a zero balance
- `POST /accounts/{account_id}/transactions` — add a credit or debit
- `GET /accounts/{account_id}/balance` — retrieve an account balance
- `GET /accounts/{account_id}/transactions` — retrieve transaction history

Transaction history accepts `type=credit` or `type=debit`, along with `page` and `limit` query parameters. The default is page 1 with 10 records per page; the maximum limit is 100. Results are ordered newest first.

## Example requests

Create an account:

```bash
curl -X POST http://127.0.0.1:8000/accounts \\
  -H 'Content-Type: application/json' \\
  -d '{"name":"Asha Patel"}'
```

Add a credit (replace `1` with the account ID returned above):

```bash
curl -X POST http://127.0.0.1:8000/accounts/1/transactions \\
  -H 'Content-Type: application/json' \\
  -d '{"type":"credit","amount":"100.00","description":"Initial credit"}'
```

Add a debit:

```bash
curl -X POST http://127.0.0.1:8000/accounts/1/transactions \\
  -H 'Content-Type: application/json' \\
  -d '{"type":"debit","amount":"25.00","description":"Purchase"}'
```

Get the balance:

```bash
curl http://127.0.0.1:8000/accounts/1/balance
```

Get credit history, latest first:

```bash
curl 'http://127.0.0.1:8000/accounts/1/transactions?type=credit&page=1&limit=10'
```

## Rules and assumptions

- Account IDs and transaction IDs are generated by the database.
- The client cannot set an account's initial balance; it always starts at zero.
- Amounts must be positive and have at most two decimal places.
- A debit is rejected when the balance is insufficient.
- The API generates a unique reference ID for every transaction and returns it in the response.
- A transaction and its balance update are committed together. The account row is locked while a transaction is processed.
- Transactions are not editable or deletable through the API.
- Invalid request data returns HTTP 422; missing accounts return 404; duplicate references return 409; insufficient balance returns 400.

This project uses `create_all` at startup for easy local setup. A production application would normally use database migrations.
